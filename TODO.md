Outcome IDs are stable. Completion means the requested product behavior is present; source data not supplied by the user remains an explicitly empty fallback.

Use the explicit, configurable Uttarakhand region/bounding-box assumption. Keep services in `/src/services`, shared modules/components in `/src`, and session-cache/fallback data under `/public/data`; never invent random observations. Label Fire Engine readiness/status, crew, water and response metrics as **Simulated**. Provide loading/empty/error states and local fallback for external data sources, keep source and last-updated information on charts/cards, create a responsive mobile/tablet/desktop shell with collapsible mobile sidebar, the ForestGuard mark and all eleven page links, top-bar search, live alert count, theme toggle and role menu, and working dark mode/reduced-motion behavior. Use the forest-green palette, Inter, consistent low/moderate/high/critical green/yellow/orange/red risk semantics, rounded cards, soft shadows, badges, skeletons and toasts; all eleven page routes work without placeholders or “coming soon” screens. Serve `/manus-routes.json` with the eleven real routes.
- [x] **FG-02 — Login / Landing:** Provide the forest hero and project tagline, clear how-it-works and data readiness/source context, and mock Admin / Forest Officer role selection saved in localStorage and visible in the navbar. State that roles are demo-only, not secure authentication.
- [x] **FG-03 — Common Dashboard:** Display the five KPIs: Active Fire Detections (24h), Forest Zones Monitored, Average Risk Score, Open Alerts, Fire Stations Nearby; show the available real hotspot/zone-risk field map, recent alert feed, risk gauge, seven-day fire trend, current-weather strip (wind, temperature, humidity), quick actions and project explanation. Use genuine loaded records only. When evidence or a required factor is missing, show an unavailable state rather than a fabricated zero; show source and update time.
- [x] **FG-04 — Forest Fire Engine:** Map and table genuine OpenStreetMap Overpass fire-station locations or supplied GeoJSON. Status options Available/Dispatched/Returning/Maintenance, crew, water level, response time and ETA must be explicitly labelled simulated. Recommend the nearest loaded station to a selected detection by straight-line distance and show the estimated ETA assumption; include a simulated response-time card, station status filter and a dispatch modal/action. Never claim live crew status, road-network routing or real emergency dispatch.
- [x] **FG-05 — Forest Health:** For each supplied zone, require monthly NDVI, Open-Meteo soil moisture, humidity, temperature and current rainfall to score. Provide vegetation trend, moisture-vs-dryness, zone comparison, colour-coded health table and zone detail drawer. Use health index `0.30×NDVI support + 0.25×soil moisture + 0.20×humidity + 0.15×temperature comfort + 0.10×rainfall support`, with every input normalized 0–100; temperature comfort is `clamp(100 − 3×|°C−20|)` and rainfall support saturates at 10 mm. Missing input means score unavailable. Label this a student educational index, not a forest survey; show honest empty states when boundaries/NDVI are absent.
- [x] **FG-06 — Vulnerable Areas:** Display supplied forest-zone polygons with calculated risk colours; ranked vulnerability table, reasons (humidity, wind, dryness/vegetation and fire frequency), risk and district filters, and click-to-open contributing-factor details. Show the fully normalized formula `0.35×fire frequency + 0.25×(100−humidity) + 0.20×wind + 0.20×dryness`; normalize factors to 0–100, cap wind at 20 m/s, use `100−soil moisture (%)` or `100−NDVI (% scale)` for dryness, and require all inputs. Missing factors are not silently zero and yield no composite score.
- [x] **FG-07 — Hotspot Simulation:** Click a map location for ignition; set wind speed/direction, humidity, temperature and fuel dryness; use an explicit Open-Meteo live-weather autofill action when available. Animate a downwind, wind-stretched ellipse unless reduced motion is preferred; choose 1/3/6/12 hours; show estimated burned hectares, spread rate and affected settlements only if authentic OSM points are loaded. Support reset and saving the scenario locally. Explain the simple non-ML formula/assumptions and that it is educational, not validated or operational guidance.
- [x] **FG-08 — Risk Change Detection:** Select Period A and Period B; provide an A/B swipe comparison map, per-zone risk change with direction/percentage, risk-over-time chart and worsened/improved/stable counts. Transparently use current environmental values for both periods, never invented historical weather, and leave scores/deltas blank when evidence is incomplete.
